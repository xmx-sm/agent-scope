# backend 参数说明

服务层统一字典传参。本文列出 `services/` 与 `core/seed.py` 的调用键、返回结构，以及 HTTP 层约定。

---

## 〇、全局约定

### 0.1 服务函数签名

```python
async def async_xxx(params: dict) -> Any:
    session = params["session"]
    ...
```

- 必填键缺失会抛 `KeyError`（属于编码错误，应在开发期暴露）
- 可选键统一用 `params.get(...)`
- 不在服务层读取 `Request`；客户端 IP 等由路由层解析后放入字典

### 0.2 通用字典键

| 键 | 类型 | 说明 |
|---|---|---|
| `session` | `AsyncSession` | 必填，数据库会话 |
| `user` / `viewer` / `operator` / `actor` | `User` | 当前操作人 |
| `data` | `dict` | 已通过 Pydantic 校验的请求体 |
| `user_id` / `target_id` / `ancestor_id` | `str` | 目标用户 ID |
| `key` / `value` / `default` | 任意 | 配置项参数 |
| `permissions` | `list[str]` | 权限键列表 |

### 0.3 返回与异常

成功统一由路由包装：

```json
{"code": 200, "data": ..., "msg": "success"}
```

业务失败抛 `ApiError`：

```python
raise ApiError("账号或密码错误", code=401)          # HTTP 401
raise ApiError("没有权限", code=403)                # HTTP 200 + code=403
raise ApiError("尝试频繁", code=429, status_code=429)
```

| code | 语义 |
|---|---|
| 200 | 成功 |
| 400 | 参数/业务校验失败 |
| 401 | 未登录、令牌失效、账号密码错误 |
| 403 | 无权限、账号禁用 |
| 404 | 资源不存在 |
| 429 | 限流 |
| 503 | 维护模式 |

`ApiError` 默认 HTTP 200，只有显式传 `status_code` 或 `code=401` 才使用真实 HTTP 状态码。

## 一、`services/auth/`

### 1.1 `rate_limit.py::async_rate_limit`

| 键 | 必填 | 说明 |
|---|---|---|
| `session` | ✅ | 数据库会话 |
| `key` | ✅ | 限流桶键，如 `rl:login:mx:127.0.0.1` |
| `max_key` | ✅ | 次数配置键，如 `login_max_attempts` |
| `window_key` | ✅ | 窗口配置键，如 `login_window_seconds` |
| `max_default` | ✅ | 配置缺失时的次数默认值 |
| `window_default` | ✅ | 配置缺失时的窗口默认值 |

返回：`None`；超限抛 429。

### 1.2 `token.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_issue_tokens` | `session`、`user` | `{access_token, refresh_token, user}` |
| `async_refresh` | `session`、`refresh_token` | 同上 |
| `async_me_payload` | `session`、`user` | `{user, permissions}`，`permissions` 为有效权限 |

### 1.3 `register.py::async_register`

| 键 | 必填 | 说明 |
|---|---|---|
| `session` | ✅ | 数据库会话 |
| `data` | ✅ | `RegisterIn` 的 `model_dump()` |
| `ip` | ✅ | 客户端 IP，用于限流 |

返回：`{user, tokens}`。受 `allow_register`、`default_role`、`password_min_length` 控制。

### 1.4 `login.py::async_login`

| 键 | 必填 | 说明 |
|---|---|---|
| `session` | ✅ | 数据库会话 |
| `account` | ✅ | 用户名/昵称/邮箱/手机号 |
| `password` | ✅ | 明文密码（仅函数内部比对） |
| `ip` | ✅ | 客户端 IP |

返回：`{access_token, refresh_token, user}`。成功后清空登录限流桶。

### 1.5 `password.py::async_change_password`

| 键 | 必填 | 说明 |
|---|---|---|
| `session` | ✅ | 数据库会话 |
| `user` | ✅ | 当前用户 |
| `old_password` | ✅ | 原密码 |
| `new_password` | ✅ | 新密码 |

返回：`None`。

## 四、`services/permissions/`

### 4.1 `role.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_role_permissions` | `session`、`role` | `list[str]` |
| `async_list_permissions` | `session` | `{permissions, all_permissions, roles}` |
| `async_update_permissions` | `session`、`role`、`permissions` | `{role, permissions}` |

### 4.2 `evaluate.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_permission_detail` | `session`、`user` | 权限详情（见下） |
| `async_effective_permissions` | `session`、`user` | 有效权限数组；超管直接全量 |

权限详情结构：

```json
{
  "user_id": "...",
  "role": "user",
  "role_permissions": ["dashboard"],
  "granted": ["permissions.team"],
  "shrunk": ["profile"],
  "temp_grants": [{"permission": "system.status", "expires_at": "..."}],
  "base": ["dashboard", "permissions.team", "profile"],
  "effective": ["dashboard", "permissions.team", "system.status"],
  "shrunk_active": ["profile"],
  "shrinkable": ["dashboard", "permissions.team"]
}
```

计算规则：

```text
基础权限 = 角色权限 ∪ granted
有效权限 = (基础权限 − shrunk) ∪ 未过期 temp_grants
```

超管：`base` 与 `effective` 恒为全部权限点。

### 4.3 `state.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_get_state` | `session`、`user_id`、`create` | `UserPermissionState \| None` |
| `split_state` | `state`（位置参数，纯函数） | `(granted, shrunk, temps)` |

### 4.4 `shrink.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_shrink_self` | `session`、`user`、`permissions` | 实际新增收缩的权限数组 |
| `async_shrink_member` | `session`、`actor`、`target_id`、`permissions` | 同上 |

规则：

- 只能收缩目标当前有效权限
- 临时授权不能被收缩
- `shrunk` 只增不减，只有超管能清空

### 4.5 `team.py::async_team_permissions`

| 键 | 必填 | 说明 |
|---|---|---|
| `session` | ✅ | 数据库会话 |
| `viewer` | ✅ | 查看人（上级） |

返回数组：`{id, username, nickname, role, is_active, permissions, shrinkable, temp_grants}`。

### 4.6 `admin.py`

| 函数 | 参数键 | 返回 |
|---|---|---|
| `async_admin_set_state` | `session`、`target`、`granted`、`shrunk`、`temp_grants`、`operator_id` | 权限详情 |
| `async_user_permission_detail` | `session`、`user_id` | 权限详情 + `catalog` |
| `async_set_user_permissions` | `session`、`user_id`、`data`、`operator_id` | 权限详情 |

`temp_grants` 允许包含超管专属权限（如 `system.status`），用于临时越级授权。
