### 设计决策

1. **业务失败 HTTP 200 + `code != 200`**，仅 401/403/404/503 使用真实 HTTP 状态码，便于前端统一用 `code` 提示。
2. **身份只信 JWT**：所有需要当前用户的接口使用 `Depends(get_current_user)`，从数据表重新读取用户，不信任前端传入的用户 ID。
3. **权限与菜单同源**：`app/permissions.py` 是权限点单一真相源，前端权限矩阵动态读取。
4. **种子幂等**：已存在的用户/配置/角色权限不覆盖，避免重启回滚管理员改过的配置。
5. **不引入 Redis / 邮件验证码**：当前为精简版，注册不需要邮箱验证码；限流等服务化阶段再补。
6. **密码哈希不依赖 passlib/bcrypt**：使用标准库 `hashlib.scrypt`，减少原生依赖与 Python 版本适配风险。

### 权限模型

```text
基础权限 = 角色权限 ∪ 超管单独授权(granted)
有效权限 = (基础权限 - 收缩(shrunk)) ∪ 未过期临时授权(temp_grants)
```

- `shrunk` 只增不减，只有超管能清空
- 临时授权优先级最高，不能被收缩，到期自动失效（读取时过滤）
- 超级管理员恒为全部权限

### 已知限制

- [ ] 限流按「账号+IP」滑动窗口，尚未实现失败次数/账户/IP 三维独立计数
- [ ] 临时授权到期没有后台清理任务（读取时过滤，不影响正确性）
- [ ] 用户管理、默认设置、权限矩阵仍为超管专属；临时越级授权目前开放只读运行状态
- [ ] 新增 `users` 列需要手工/启动迁移，新增表仍需注意存量库
