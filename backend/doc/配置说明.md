# backend 配置说明

配置分三层：

1. **启动参数**：`backend/.env`，进程启动时读取，修改后需重启。
2. **系统配置**：`system_configs` 表，超管在「默认设置」页修改，即时生效（个别项需重新登录）。
3. **代码常量**：权限点、配置定义、默认角色权限，改代码后需发布。

| key | 默认 | 范围 | 说明 |
|---|---|---|---|
| `runtime.ai_max_concurrent_streams` | 8 | 1~128 | 单进程 AI/SSE 生成任务上限，超限返回 429 |
| `runtime.rag_max_concurrent_searches` | 4 | 1~32 | 单进程知识库检索上限 |
| `runtime.external_call_max_concurrency` | 16 | 1~128 | 单进程 A2A、TTS、模型列表等出站调用上限 |
| `runtime.stream_event_buffer_bytes` | 2097152 | 65536~16777216 | 每个任务的断线续传事件缓冲上限 |
| `runtime.stream_retention_seconds` | 600 | 30~3600 | 完成后续传状态保留时间 |
| `runtime.stream_max_duration_seconds` | 900 | 60~7200 | 单次 AI 生成超时时间 |

运行配置在本进程更新后即时失效缓存，并保留 5 秒 TTL 兜底。当前并发计数为进程内实现，多 Worker 时上限按进程计算；严格全局限流需要 Redis 或分布式调度。

### 界面

| key | 默认 | 类型 | 说明 |
|---|---|---|---|
| `default_page_size` | 10 | int | 列表默认条数 |
| `status_refresh_seconds` | 10 | int | 运行状态刷新间隔（前端当前固定 10 秒，预留） |

### 读取优先级

```text
数据库 system_configs  >  CONFIG_DEFINITIONS 默认值  >  调用方传入 default
```

新增配置项只改 `CONFIG_DEFINITIONS`，启动时 `async_seed` 自动补缺失行；已有值不会被覆盖。
恢复默认通过 `POST /api/admin/configs/{key}/reset`。

## 三、Redis 与限流

### 3.1 连接策略

1. 先做 1 秒 TCP 探活，结论缓存 60 秒
2. 端口通后再 `PING`，3 秒超时
3. 任一失败 → 客户端为 `None`，限流降级进程内滑动窗口
4. 降级不是“放行”，仍然按同样的次数/窗口限制

### 3.2 限流键

| 场景 | 键 |
|---|---|
| 登录 | `rl:login:<account>:<ip>` |
| 注册 | `rl:register:<ip>` |

- Redis 使用 zset 实现滑动窗口：`ZREMRANGEBYSCORE` + `ZCARD` + `ZADD` + `EXPIRE`
- 登录成功会清空当前登录桶
- 运行状态页展示 `rate_limit_backend`（redis/memory）与桶数量

### 3.3 调整限流

超管在「默认设置 → 安全」修改后即时生效；关闭 `rate_limit_enabled` 后登录/注册不再限流。

## 四、权限配置

权限点定义在 `app/core/permissions.py`。

| 权限点 | 名称 | 可分配 | 说明 |
|---|---|---|---|
| `dashboard` | 工作台 | ✅ | 工作台页面 |
| `profile` | 个人中心 | ✅ | 个人资料 |
| `permissions.self` | 我的权限 | ✅ | 自我收缩 |
| `permissions.team` | 团队权限 | ✅ | 收缩下属 |
| `ai.use` | 使用 AI | ✅ | 调用 AI 能力 |
| `ai.config` | AI 配置管理 | ❌ 超管专属 | 修改 AI 默认配置 |
| `admin.users` | 用户管理 | ❌ 超管专属 | 用户增删改 |
| `admin.settings` | 默认设置 | ❌ 超管专属 | 配置与角色矩阵 |
| `admin.permissions` | 权限配置 | ❌ 超管专属 | 角色权限矩阵 |
| `admin.menus` | 菜单配置 | ❌ 超管专属 | 默认菜单维护 |
| `system.status` | 运行状态 | ❌ 超管专属 | 可通过临时授权开放 |

角色默认：

```text
super_admin: 全部权限
admin:       dashboard, profile, permissions.self, permissions.team, ai.use
user:        dashboard, profile, permissions.self, ai.use
```

### 有效权限

```text
基础权限 = 角色权限 ∪ 超管单独授权
有效权限 = (基础权限 − 逐级收缩) ∪ 未过期临时授权
```

- 收缩只增不减，只有超管能清空
- 临时授权到期自动失效（读取时过滤）
- 超管恒为全部权限

## 五、数据库

- 连接串来自 `DATABASE_URL`
- 连接池参数来自 `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` / `DB_POOL_TIMEOUT` / `DB_POOL_RECYCLE`，修改后需重启
- 所有应用进程的连接池上限合计应小于 PostgreSQL `max_connections`，并为管理、迁移和监控预留连接
- 启动时 `create_all` 建缺失表
- 存量表新增列不会自动补，已知列在 `init_db` 内做幂等 `ALTER`
- 表结构见 [数据库说明.md](./数据库说明.md)

## 十一、v0.5.0 AI 工具权限

### 模型

- `user_tool_modes`：`all` / `custom`
- `user_tool_permissions`：用户 + 工具组 + 工具名，`enabled`、`granted_by`

### 语义

```text
默认 = 全部工具可用
单独授权 = 超管切换 custom 并勾选工具/工具组
收窄 = 上级或本人关闭已授权工具
```

- 上级只能管理管理链上的下属
- 上级不能打开自己都没有的工具
- 本人只能关闭工具，不能自行扩权
- 超管保存 custom 清单时具有最终权威，会清空旧收窄行
- `恢复全部工具` 会回到 `mode=all` 并清空收窄

### 当前工具组

basic / db / net / mail / mcp / system / rag。

## 十二、v0.7.0 AI 安全默认值

### AI 安全

| key | 默认 | 说明 |
|---|---|---|
| `security.prompt_guard_enabled` | true | 构建 Agent 时追加安全提示词 |
| `security.prompt_guard_text` | 内置约束 | 防越狱提示词，可自定义 |
| `security.identity_lock` | true | 丢弃模型传入的 `user_id` / `_` 内部键，再压服务端身份 |
| `security.allow_model_db_config` | false | 默认禁止模型自传数据库连接 |
| `security.allow_model_file_paths` | false | 默认禁止模型自传文件路径 |

> 提示词只是软约束。真正的安全边界依赖：服务端身份锁定、工具权限过滤、数据库白名单、文件路径服务端注入、审批与审计。

### 数据库安全

| key | 默认 | 说明 |
|---|---|---|
| `db.allow_all_tables` | false | 关闭时只允许白名单表 |
| `db.allowed_databases` | 空 | 可读库；空=不限制库 |
| `db.allowed_tables` | 空 | 可读表；**空且未允许全部=任何表都不可读（fail-closed）** |
| `db.denied_databases` | 空 | 禁读库，一票否决 |
| `db.denied_tables` | 空 | 禁读表，一票否决 |
| `db.allow_write` | false | 默认禁止数据库写入 |

判定公式：

```text
可读 = 库∉denied_databases ∧ 库∈allowed_databases(空=不限)
       ∧ 表∉denied_tables
       ∧ (allow_all_tables ∨ 表∈allowed_tables)
```

### 接口

- `GET /api/admin/security/policy`：读取安全默认值
- `POST /api/admin/security/db/check`：按默认策略检查 `库.表` 是否可读

### 参考的 agent_study 文档结论

- 只改提示词不算修好（安全审计文档）
- 身份只信 JWT；模型参数中的 `user_id` 与下划线内部键必须丢弃
- DB 白名单/黑名单必须在服务端覆盖模型自传 `db_config`
- 读写同权、默认拒绝、能力只能收紧
