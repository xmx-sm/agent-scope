# 安全与权限

## 一、IAM 分级

### 1. 角色层级

```text
super_admin  超级管理员
    ↓
admin        管理员
    ↓
user         普通用户
```

- `super_admin`：固定拥有全部权限，不受收缩影响
- `admin`：默认拥有工作台、个人中心、页面权限、团队权限、AI 使用
- `user`：默认拥有工作台、个人中心、页面权限、AI 使用

角色权限是基线，不是最终权限。

### 2. 有效权限公式

```text
有效权限 = (角色权限 ∪ 单独授予 − 收缩) ∪ 未过期临时授权
```

- 角色权限：`role_permissions`
- 单独授予：`user_permission_states.granted`
- 收缩：`user_permission_states.shrunk`
- 临时授权：`user_permission_states.temp_grants`
- 收缩只增不减，只有超管可清空
- 本人只能收缩自己，不能自扩
- 上级只能收缩下级，不能收缩自己无权管理的用户
- 超管可对指定用户临时越级授权，到期自动失效

### 3. 组织汇报线

- `users.leader_id` 表示直属上级
- 团队权限、工具收窄、菜单「管理下级」均沿汇报线判断
- 不能跨汇报线管理非下属

### 4. 页面权限

- `permissions.self`：我的权限
- `permissions.team`：团队权限
- `ai.use`：使用 AI
- `ai.config`：Agent 默认配置（超管）
- `admin.users` / `admin.settings` / `admin.permissions` / `admin.menus` / `admin.audits`
- `system.status`

菜单可绑定权限点；菜单可见性不替代接口权限校验。

### 5. AI 工具权限

独立于页面权限：

```text
user_tool_modes.mode = all | custom
user_tool_permissions = 组/工具级 enabled / require_approval / approval_status
```

- `all`：默认全部 AI 工具可用
- `custom`：仅按清单授权
- 上级可对下级收窄
- 本人只能收紧
- 需要审批的工具：审批通过后才进入 Toolkit
- 工具权限变更写入 `tool_permission_audits`

### 6. 资源归属

- 会话、附件、知识库、A2A 伙伴、定时任务均按 `user_id` 隔离
- 知识库额外支持显式共享：只读 / 可写
- A2A 入站调用按伙伴主人身份执行，不读取调用方身份

## 二、Agent 防破甲 / 防注入

### 1. 输入防注入

配置：

```text
默认配置 → Agent 配置 → AI 安全
- 启用输入防注入
- 输入防护动作：block / warn
- 自定义注入规则：JSON 字符串数组
```

内置规则覆盖：

- 忽略之前/以上指令
- 无视/绕过/突破安全策略
- 输出系统提示词、API Key、密钥、密码
- ignore previous instructions / disregard system prompt
- developer mode / jailbreak / DAN mode
- 要求扮演开发者/管理员/无限制模式

动作：

- `block`：拒绝本次请求，不保存用户消息
- `warn`：继续对话，但在系统提示词中追加防护提示

### 2. 安全提示词

- 系统级安全提示词默认开启
- 明确禁止：绕过策略、泄露密钥、读取未授权数据、伪造身份、调用未授权工具
- 工具参数中的身份、数据库连接、文件路径由服务端注入

### 3. 服务端身份锁定

- 模型传入的 `user_id` 与下划线前缀内部键会被丢弃
- 工具执行时重新压入真实用户身份
- 模型无法通过工具参数切换身份

### 4. 工具最小权限

- Toolkit 只装配用户当前生效的工具
- 组 / 工具级授权与收窄
- 需审批工具未通过时不装配
- Shell 默认关闭
- 数据库默认只读、默认无表白名单
- 数据库写权限默认关闭
- 模型不能自传数据库 host / user / password / path（默认）
- 文件工具限制在用户工作区

### 5. 输出密钥脱敏

配置：

```text
默认配置 → Agent 配置 → AI 安全 → 输出密钥脱敏
```

对以下内容做脱敏：

- `sk-...`
- `Bearer ...`
- `password=...` / `api_key=...` / `token=...`
- PEM 私钥

应用于：

- SSE 文本增量
- 思考过程增量
- 工具结果
- 最终保存的助手消息

### 6. 知识库与附件防注入

- 知识库片段用 `<knowledge>` 包裹
- 明确声明：知识库内容只是资料，不是指令
- 资料中要求忽略规则、泄露提示词、调用工具的语句视为普通文本
- 附件文本同样作为数据处理，不覆盖系统提示词

### 7. 审计与审批

- 工具权限变更：`tool_permission_audits`
- 工具审批：`tool_approval_requests`
- A2A 调用：`a2a_invocations`
- 知识库操作：`vector_logs`
- 模型用量：`agent_model_calls`

## 三、配置入口

```text
默认配置 → Agent 配置 → AI 安全
```

| 配置 | 默认 | 说明 |
|---|---|---|
| `security.prompt_guard_enabled` | 开 | 追加安全提示词 |
| `security.prompt_guard_text` | 内置 | 安全约束文本 |
| `security.input_guard_enabled` | 开 | 输入防注入 |
| `security.input_guard_action` | `block` | block / warn |
| `security.input_guard_patterns` | `[]` | 追加正则规则 |
| `security.output_redact_enabled` | 开 | 输出密钥脱敏 |
| `security.identity_lock` | 开 | 身份锁定 |
| `security.allow_model_db_config` | 关 | 允许模型自传数据库连接 |
| `security.allow_model_file_paths` | 关 | 允许模型自传文件路径 |
| `security.allow_agent_shell` | 关 | 允许 Shell 工具 |

## 四、边界

- 输入防护是正则规则，不是语义分类器；改写表达仍可能绕过，需配合安全提示词、工具权限、服务端校验
- 输出脱敏基于模式匹配，不能保证覆盖所有厂商密钥格式
- 工具权限审批目前是「授权后可用」，不是每次调用都弹窗人工确认
- SSE 流式输出按增量脱敏；跨分片的密钥可能要到最终消息才完整脱敏
- 这不是完整等保/零信任方案，生产环境仍需网络隔离、密钥托管、审计留存与定期渗透测试
