# scope/tools 参数说明

本文档说明 `scope/tools/` 下**五个工具域**的入口函数、`data["function"]` 清单、各功能的入参与返回契约。
（`crawl` 原独立成域，第三轮已合并回 `net` 作「高级网络请求」。）
**各域默认值（端口/超时/上限/主机名等）自第四轮起从 `config.db` 读取**，优先级 data > sqlite > None，
完整配置项表与三类语义见《配置说明.md》；本文档的入参表中标「缺省」处即指该 config 项。

- `tools/system/` 系统工具（`async_sys_tools` → `cmd_run`）
- `tools/net/` 网络工具，**两个入口**：
  - `async_req_tools` 基础网络（天气 / 城市 ID / HTTP / 下载）
  - `async_crawl_tools` **高级网络**（crawl4ai 浏览器渲染 / 截图 / PDF，可选依赖）
- `tools/mail/` 邮件工具（`async_email_tools` → 收发 / 查找）
- `tools/mcp/` MCP 客户端（`async_mcp_client` / `async_mcp_tools`）
- `tools/db/` 数据库读写（`async_db_tools` 只读 / `async_db_write_tools` 写，PG / MySQL / MongoDB / SQLite）

类型标注：`str` 字符串 / `int` 整数 / `float` 小数 / `bool` 布尔 / `dict` 字典 / `list` 列表 / `None` 可空。

统一返回格式：`{"code": 200|400|500, "data": ..., "message": "..."}`（200 成功 / 400 参数或权限错误 / 500 内部异常）。

---

## 〇′、入参与返回的统一约定（2026-11-22 改造后）

> 默认值的存储与读取（config 层）见《配置说明.md》。本节只讲函数入参形态与返回信封契约。

五个域的**全部 127 个顶层函数**已统一形态，这是改造后的基线契约：

| 项 | 约定 |
|---|---|
| 入参 | 一律 `data: dict = None`，位置参数与 `**kwargs` 全部取消 |
| 参数错误 | 一律 **`if` 判断后返回 400 信封**，不再裸抛异常 |
| 返回 | 一律 `{"code": 200\|400\|500, "data": ..., "message": ...}` |
| 错误位置 | `data` 在 400/500 时为 `<文件绝对路径>_<函数名>` |
| 前缀 | 校验类错误带「错误：」前缀；路由提示（「暂不支持的 function」）**不带**（沿用原件差异，见踩坑记录 A19） |

### 两类豁免

**① 信封机器（19 个）** —— `_ok` / `_err` / `_where` / `_to_bool_tuple` / `_bad_limit`。
它们**造信封或拆信封**，自身必须保持原生签名；否则 `return _ok(x)` 得写成
`return _ok({"x": x})` 再由调用方解开，纯属绕圈。这是唯一不守"data 入参"规则的函数族。

**② 纯副作用函数（6 个，其中 5 个在 net）** —— 入参改成 data，但**不套信封**（无数据可返回）：

| 函数 | 位置 | 做什么 |
|---|---|---|
| `configure_fs_policy` | `net/_fs.py` | 写 `_HOST_CTX`（平台装配时注入闸门） |
| `_apply_wait_for` | `net/_render.py` | 改 `run_cfg.js_code` |
| `_clamp_configs` | `net/_render.py` | 原地钳制 run_cfg / br_cfg |
| `_apply_extraction` | `net/_render.py` | 改 `run_cfg.extraction_strategy` |
| `_reset_crawler` | `net/_crawler.py` | 关单例并置 None |
| `_wait_imap_hello` | `mail/_connection.py` | 等握手，失败即 raise |

它们对**坏入参 fail-fast 抛 `ValueError`**——调用点是自己写的代码，传错类型属编程错误，
应当尽早崩掉而不是被吞成 400。

### 活对象放在 data 里

返回连接、客户端、配置对象、SSL context 这类**不可 JSON 序列化**的活对象时，
`data` 直接就是那个对象（不再套一层命名键），以降低解包噪音：

```python
client = get_http_client({"verify": True})["data"]          # 直接是 httpx.AsyncClient
conn   = (await async_open_imap({"cfg": cfg}))["data"]      # 直接是 aioimaplib 连接
crawler = (await _get_crawler({"browser_cfg": br_cfg}))["data"]
```

例外：一次返回**多个**值时才用命名字典，如 `build_client(...)["data"]["client"]`、
`_write_where(...)["data"]["where"]`。

⚠️ 返回的共享实例**不得 `aclose()`**（`get_http_client` 是进程级单例，关掉会连带影响后续所有请求）。

### 行为差异一览（相对改造前）

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 非 dict 入参 | `mcp`/`db` 裸抛 `AttributeError`/`ValueError` | 400 信封 |
| 非法列名当 filters | `db` **静默丢掉该条件照常查询**（返回残缺结果集） | 400 报错 |
| 非法列名当 order_by | 静默忽略排序 | 400 报错 |
| 畸形 date_from | `mail`/`db` 静默跳过该条件 | 400 报错 |
| 坏端口配置（`smtp_port:"abc"`） | `mail` 裸抛 `ValueError` | 400 报错 |
| 表不存在 / 主键冲突 | 500「数据库查询失败：OperationalError…」 | 400「SQLite 读执行失败：…」 |
| `limit:"abc"` | 400「invalid literal for int() with base 10: 'abc'」（内部异常文案泄漏） | 400「limit / offset 必须是整数」 |
| `crawl4ai` 未安装 | 裸抛 `ModuleNotFoundError` | 400 信封，附 pip 安装指引 |
| 驱动未安装（asyncpg/aiomysql/pymongo） | 裸抛 `ImportError` | 400 信封，附 pip 指引 |
| `downloads_path` 越界 | `ValueError` **穿透到调用方** | 400 信封 |
| db 错误位置 | 全部报 `_const.py_async_db_tools` | 报实际出错模块（`gate.py`/`executors.py`…） |
| mail 分页元数据 | 挂在信封**顶层** | 收进 `data`（**平台侧需改**，见第四节） |

## 〇、全局调用契约（先读这个，最容易错）

四条硬约束，五个域通用，均源于实测：

1. **业务参数平铺在 `data` 顶层**，不嵌在 `arguments` 子字典里。
   `{"function":"count_table","table":"orders"}` ✅ ／ `{"function":"count_table","arguments":{"table":"orders"}}` ❌（后者报「非法表名: None」）
2. **错误字段名是 `message`，不是 `msg`。** 写错会拿到 `None` 而以为"没报错"。
3. **经 agentscope `FunctionTool` 调用时，模型必须传 `{"data": {...}}` 一层包裹。**
   `Toolkit.call_tool` 会把 `input` JSON **展开成 kwargs**，而这些函数签名是 `(data: dict)`。
   直接传 `{"function":"..."}` 会得到 `async_db_tools() got an unexpected keyword argument 'function'`。
   这也是模型看到的 schema 是 `{"data": {"additionalProperties": true}}` 黑盒的由来——`data` 是**参数名**，不是业务字段。
4. **自测块用 `python -m`，不能直接跑文件。**
   `python -m tools.system.main_sys` ✅ ／ `python tools/system/main_sys.py` ❌（`ImportError: attempted relative import with no known parent package`）

导入方式（`scope` 在 `sys.path` 上时）：

```python
from tools.db.main_db import async_db_tools, async_db_write_tools
from tools.net.main_net import async_req_tools
from tools.system.main_sys import async_sys_tools
from tools.mail.main_mail import async_email_tools
from tools.crawl.main_crawl import async_crawl_tools, configure_fs_policy
from tools.mcp.main_mcp import async_mcp_tools
from tools.mcp.client import async_mcp_client
```

各域 `main_*.py` 是唯一入口，功能模块不应被业务代码直接调用（`db` 的方言入口 `_pg`/`_my`/`_lite`/`_mongo` 除外，它们只被 `main_db` 调）。

## 一、`tools/db/` — 数据库工具

两个入口，按读写分离（写是高危，平台可在工具级单独停用）：

⚠️ 两个入口都**没有** `isinstance(data, dict)` 防护：`None` 会被 `dict(data or {})` 宽容转成空 dict 后正常报错，
但字符串/列表/整数入参**裸抛 `ValueError`/`TypeError`）。改造前五个域里只有 mail/net/system 三个有完整防护，
`db` 与 `mcp` 都没有（见踩坑记录 A12、A13；本轮已全部补齐）。

### `async_db_tools(data)` — 只读查询

`FUNCTIONS = ("list_databases", "list_tables", "describe_table", "table_data", "count_table", "run_query")`

| 入参 (data) | 类型 | 必填 | 说明 |
|------|------|------|------|
| `function` | `str` | 是 | 上表六者之一 |
| `db_config` | `dict` | 是 | 连接配置，见下；也可平铺在 data 顶层（`db_config` 优先） |
| `database` | `str` | 否 | 本次操作的目标库，覆盖 `db_config.database`；SQLite 文件夹模式下是文件名（可省后缀） |
| `pattern` | `str` | 否 | 仅 `list_tables`：`%` 通配筛选表名 |
| `table` | `str` | 条件 | `describe_table`/`table_data`/`count_table` 必填；标识符校验，仅允许字母数字 `_` `$`，最多 `schema.table` |
| `columns` | `list[str]` | 否 | 仅 `table_data`：指定返回列 |
| `filters` | `dict` | 否 | `table_data`/`count_table`：等值，或 `{"like":"%x%"}` / `{"gte":n}` / `{"lte":n}`，AND 拼接 |
| `order_by` | `str` | 否 | 仅 `table_data`：`"列名"` 或 `"列名:desc"` |
| `offset` / `limit` | `int` | 否 | 仅 `table_data`：分页，`limit ≤ 500`（`_MAX_ROWS` 服务端钳制） |
| `sql` | `str` | 条件 | 仅 `run_query`：只读 SQL，起始词限 `select/with/show/desc/describe/explain` |

返回：`data` 形状随 function 而变——`list_databases` 为 `["orders.db"]`；`list_tables` 为 `[{"schema","table"}]`；`describe_table` 为 `[{"column","type","nullable","default","primary_key"}]`；`count_table` 为 `{"count": N}`；`table_data` 为 `{"rows":[...], "returned": N}`；`run_query` 为 `{"columns":[...], "rows":[...], "truncated": bool}`。

### `async_db_write_tools(data)` — 写操作

`WRITE_FUNCTIONS = ("insert_row", "update_rows", "delete_rows", "run_write")`

| 入参 (data) | 类型 | 必填 | 说明 |
|------|------|------|------|
| `function` | `str` | 是 | 上表四者之一 |
| `db_config` | `dict` | 是 | 同上，且 `allow_write` 不得为 `false` |
| `table` | `str` | 条件 | `insert_row`/`update_rows`/`delete_rows` 必填 |
| `data` | `dict` | 条件 | `insert_row`/`update_rows` 的行数据。**键是 `data`，不是 `values`**；值必须是标量（拒嵌套 dict/list） |
| `filters` | `dict` | 条件 | `update_rows`/`delete_rows` **必填且非空**，拒绝全表操作 |
| `sql` | `str` | 条件 | 仅 `run_write`：单条 `insert/update/delete`；`update/delete` 必须含 `WHERE`；DDL 与多语句拒绝 |
| `database` | `str` | 否 | 目标库 |

返回：`{"table": ..., "affected": N, ...}`。影响行数超 `_MAX_AFFECT = 100` **自动回滚**并报错。

### `db_config` 连接字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `db_type` | `str` | **必填**（调用传入或 `config.db` 的 `db.type`，两处都没有报「缺少参数 db_type」）：`postgresql`（接受 `postgres`/`pg`）/ `mysql` / `mongodb`（接受 `mongo`）/ `sqlite`（接受 `sqlite3`） |
| `host` `port` `user` `password` `database` | — | 服务端型；`port` 同样**无源码兜底**：调用或 `config.db` 的 `db.port.<类型>` 必须提供；`database` 对 PostgreSQL/MongoDB 必填（无 `postgres`/`admin` 兜底） |
| `path` | `str` | **SQLite 单文件模式**：数据库文件路径 |
| `dir` | `str` | **SQLite 文件夹模式**：目录内放多个 `.db/.sqlite/.sqlite3`，调用时用 `database` 指定文件名 |

`path` 与 `dir` 二选一。SQLite 特有约束：只读以 `mode=ro` URI 打开（**连接层即无法写库**）；写操作要求目标文件已存在（不自动建库，防随手生成垃圾 db）；文件夹模式下 `database` 仅接受纯文件名（拒路径分隔符与 `..`）；`attach`/`detach`/`pragma` 一律拒绝。

### `db_config` 管控字段（平台/管理端注入，模型传参无法覆盖）

| 字段 | 类型 | 说明 |
|------|------|------|
| `allowed_databases` | `list[str]` | 可操作库白名单，空 = 不限；`list_databases` 也只回名单内 |
| `allowed_tables` | `list[str]` | 可读表白名单；条目 `"库名.表名"` 或裸表名（全库同名表），不分大小写 |
| `denied_databases` | `list[str]` | 黑名单，**一票否决**，优先级最高（白名单为空也生效） |
| `denied_tables` | `list[str]` | 同上 |
| `allow_write` | `bool` | `false` 时写工具整体禁用 |

安全行为（`gate.py`）：

- 命中黑名单与"不在白名单"**返回同款文案**，不透露对象存在性。
- 系统目录（`information_schema`/`pg_catalog`/`mysql`/`performance_schema`/`sys`）与 SQLite 内部表（`sqlite_*`）一律拒绝。
- 管控生效时，`run_query`/`run_write` 用 **sqlglot 提取 SQL 引用的全部表**逐一判定，**无法完整解析即拒绝（fail-closed）**，且仅允许单条语句。
- `list_tables`/`list_databases` 的输出同步过滤，黑名单对象不可见。

实测闸门拦截样例（`_err` 的位置标识已改为指向实际出错模块，见 〇′）：

| 尝试 | 结果 |
|------|------|
| `run_query` 发 `DELETE FROM orders` | 400 「仅允许单条 select/with 语句」 |
| 查 `sqlite_master` | 400 「表 'sqlite_master' 不在可访问范围内」 |
| 越权库 `secrets` | 400 「数据库 'secrets' 不在可操作白名单内」 |
| `SELECT 1; ATTACH DATABASE '/etc/x' AS y` | 400 「仅允许单条语句」 |
| `update_rows` 不带 `filters` | 400 「update/delete 必须携带非空 filters…禁止全表操作」 |
| `run_write` 发 `DROP TABLE` | 400 「run_write 仅允许 insert/update/delete」 |

### db 域本次新增的校验（原实现静默放过，会给出**错误结果**而非报错）

| 输入 | 原行为 | 现行为 |
|---|---|---|
| `table_data.filters` 含非法列名（如 `"bad col;"`） | **静默丢掉该条件照常查询**，返回少了条件的结果集，`code=200` | 400「非法列名: 'bad col;'」 |
| `table_data.order_by` 非法列名 | 静默忽略排序，返回未排序数据 | 400「非法列名」 |
| `order_by` 写 `"amount:sideways"` | 静默忽略方向 | 400「order_by 仅支持 "列名" 或 "列名:asc\|desc"」 |
| `filters` 某列条件对象为空 `{}` | 静默忽略该条件 | 400「列 amount 的条件对象为空」 |
| `limit`/`offset` 非整数 | 400 但文案是 Python 内部异常 `invalid literal for int() with base 10: 'abc'` | 400「limit / offset 必须是整数」 |
| 表不存在 / 主键冲突 | **500**「数据库查询失败：OperationalError…」 | **400**「SQLite 读执行失败：OperationalError…」（属参数问题，不属内部异常） |
| 非 dict 入参（str/list/int） | **裸抛** `ValueError`/`TypeError`（`None` 则宽容） | 400「data 必须是字典对象，收到 str」 |

前五项是**安全或正确性**改进：非法列名静默跳过最危险——模型拿到的是看似成功
（`code=200`）实则缺条件的数据，无从发现。第六项让 500 专留真正的内部/连接故障。

## 二、`tools/net/` — 网络工具（基础 + 高级，两个入口）

`crawl` 原独立成域，后按用户决策**合并回 net**，定位「高级网络请求」——
依据是 `agent_study/tools/__init__.py` 本就把 `async_crawl_tools` 挂进 `ToolGroup("net")`。
两个入口保持独立 FunctionTool（平台可单独停用 crawl 而保留 http_request），
装配时挂**同一个** `ToolGroup("net")`，模型一次 `reset_tools` 同时拿到。

### `async_req_tools(data)`

| `function` | 入参 (data) | 说明 |
|------|------|------|
| `http_request` | `url`(必填), `method`, `headers`, `params`, `data`, `json`, `verify`, `response_type`, `max_length`, `timeout` | 通用 HTTP 请求。`method` 缺省 GET 且大小写不敏感；`response_type` 控制返回文本/JSON/二进制 |
| `download` | `url`(必填), `save_path`(必填), `max_size`, `report_every`, `verify` | 文件下载，`max_size=0` 表不限。⚠️ **本域唯一的流式工具**，直接 `await` 拿到的是 async_generator，见踩坑记录 A4/A5 |
| `get_weather` | `city_id`(必填) | sojson 免费城市天气，`city_id` 形如 `"101030100"` |
| `getcityid` | `city_name`(必填) | 城市名 → 城市数字 ID，供 `get_weather` 使用 |
| `get_weather_wttr` | `city`(必填), `format` | wttr.in 天气 |

返回：`http_request` 为 `{"status_code","reason","headers","content","truncated","json"}`；`download` 为保存路径与大小信息。

共享件：`_client.py` 持进程级 httpx 客户端单例（`_HTTP_CLIENT`，上限 1000 连接 / 200 keepalive）与 `get_timeout` 归一化。`timeout` 缺省 5 秒，必须为正数。

### `async_crawl_tools(data)` — 高级网络（crawl4ai 浏览器渲染）

### `async_crawl_tools(data)`

| `function` | 入参 (data) | 说明 |
|------|------|------|
| `crawl` | `url`(必填), `run_config`, `browser_config`, `output_format`, `max_length` | 单页抓取（JS 渲染） |
| `crawl_many` | `urls`(必填 list) | 批量，上限 `_BATCH_URLS_MAX = 20` |
| `deep_crawl` | `url`(必填), `max_depth`, `accept_url_patterns`, `ignore_url_patterns`, `total_limit`, `concurrent_limit`, `run_config`, `browser_config`, `output_format`, `max_length` | 站内深爬，页数上限 `_DEEP_PAGES_MAX = 30` |
| `screenshot` | `url`(必填), `save_path`(必填), `css_selector`, `full_page`, `wait_ms`, `run_config` | 页面截图落盘 |
| `extract_pdf` | `pdf_path` 或 `url`, `max_length` | PDF 结构化抽取 |

`run_config` / `browser_config` **透传 crawl4ai 官方参数原样**（不发明同义字段）；无效参数返回 `valid_params` 名单供模型自纠。

服务端硬钳制（模型传参无法突破）：`page_timeout ≤ 120_000 ms`、信号量 `≤ 5`、爬虫回收周期 `≤ 50`、`max_length` 缺省 `20_000`、rerank 候选上限 `50`。

### `configure_fs_policy(check_write=None, check_read=None, allow_headed=False)`

**平台装配时必须调用**。注入文件闸门：`check_write/check_read(path) -> (bool, str)`。

- 未注入时闸门**放行**（高代码单机场景）——线上必须注入，否则全盘可写。
- 独立模式有默认兜底闸门：仅允许当前工作目录，越界返回 400「保存路径被拒：超出可写入范围」。
- `allow_headed` 控制是否允许有头浏览器。

⚠️ crawl4ai 是**函数内延迟导入**：未安装时模块照常加载、`async_crawl_tools` 路由正常，只在进入 `crawl`/`crawl_many`/`deep_crawl` 时抛 `ModuleNotFoundError`。`screenshot`/`extract_pdf` 未装也能跑到闸门校验。

## 三、`tools/mail/` — 邮件工具

### `async_email_tools(data)`

| `function` | 入参 (data) | 说明 |
|------|------|------|
| `send_email` | `email`(必填), `subject`, `content`, `html`, `attachments` | 发送邮件。`email` 是**发件邮箱地址**（缺失报「data 中缺少 email 字段」），收件人在 `to` |
| `to_mail` | 同 `send_email` | **`send_email` 的兼容别名**，原代码即如此，勿删 |
| `receive_email` | `offset`(缺省 0), `count`(缺省 10), `mailbox`, `save_attachments`, `attachment_dir` | 按条件收取，分页 |
| `find_email` | `keyword`, `subject`, `sender`, `date_from`, `date_to`, `offset`, `count`, `save_attachments`, `attachment_dir` | 按条件查找。**四个条件至少给一个**，否则 400「keyword / subject / sender / date_from / date_to 至少一个」 |

`filters` 类日期条件用 `date_from`/`date_to`，IMAP 侧换算为日期准则（`build_date_criteria`），必要时客户端侧二次过滤（`async_filter_ids_client_side`）。

配置：`email_config`（也可平铺顶层），`get_email_config` 做"data 覆盖 > config.db > 空"归一化。`smtp_host`/`smtp_port`/`imap_host`/`imap_port` 属连接身份类参数，**无源码兜底**：`get_email_config` 不再填默认服务器/端口，实际发信或收信时仍缺则由连接函数报「缺少参数 xxx」；缺邮箱地址仍报「缺少邮箱地址 (email_config.email)」。

### ⚠️ 返回契约变更（两处破坏性变更之一，另一处是 `download` 的闸门）

`receive_email` 与 `find_email` 的分页元数据**原先挂在信封顶层**（非标准形状），
经入口透传后成为对外契约。现统一进 `data`：

```python
# 改造前
{"code":200, "data":[邮件...], "total":611, "offset":0, "count":10,
 "has_more":true, "message":"命中 611 封，返回 10 封"}

# 改造后
{"code":200,
 "data":{"emails":[邮件...], "total":611, "offset":0, "count":10, "has_more":true},
 "message":"命中 611 封，返回 10 封"}
```

**平台侧要改的读取代码**：

| 改造前 | 改造后 |
|---|---|
| `r["data"]` | `r["data"]["emails"]` |
| `r["total"]` | `r["data"]["total"]` |
| `r["has_more"]` | `r["data"]["has_more"]` |
| `r["offset"]` / `r["count"]` | `r["data"]["offset"]` / `["count"]` |

`send_email` 的返回形状未变（`data` 一直是发件详情字典）。

## 四、`tools/system/` — 系统工具

### `async_sys_tools(data)`

只有一个 `function`：

| `function` | 入参 (data) | 说明 |
|------|------|------|
| `cmd_run` | `command`(必填), `timeout`(缺省 30), `shell`(缺省 True), `capture_output`(缺省 True), `text`(缺省 True), `encoding`(缺省 "utf-8"), `errors`(缺省 "ignore"), `output_limit`(缺省 0=不限), `output_part`(缺省 "tail") | 执行 Shell 命令，**高风险，需人工审批** |

`timeout` 必须 > 0；布尔项容忍字符串写法（`"true"/"1"/"yes"/"on"` 与 `"false"/"0"/"no"/"off"/"n"`），其他字符串报「必须是布尔值」——**注意 `"yes"` 会被接受为 True**，若平台想严格化需改 `_common.get_common_args`。

`output_part` 限 `head` / `tail` / `middle` 三者，其他值 400。

返回：`{"stdout","stderr","return_code","os_type","truncated","skipped","timed_out"}`；超时 `message` 为「命令执行超时，已返回部分输出」而非报错——**调用方须查 `timed_out` 判断是否完整**。

实现要点：`asyncio.create_subprocess` 原生异步（不占线程池）；Windows 自动指定 `cmd.exe`；超时后 kill 但仍返回已收集的部分输出。

## 五、`tools/mcp/` — MCP 客户端

### `async_mcp_client(data)`

建立 MCP 连接，返回客户端列表。

| 入参 (data) | 类型 | 必填 | 说明 |
|------|------|------|------|
| `mcp` | `dict` | 否 | `mcpServers` 配置，key 为 server 名；也接受 `config_path` 指向 json 文件 |

配置缺省读 `_config.py` 同目录的 `mcp_servers.json`（`DEFAULT_MCP_CONFIG`）。未配置报 400「未配置 MCP」。

工具名前缀约定：`mcp__{name}__*`，由 `build_client` 产出。stdio 与 http 两种传输由配置字段（`command` 或 `url`）自动判别。

⚠️ **mcp 全域没有入参类型检查**：传 `None`/`"notdict"`/`123` 一律抛 `AttributeError` 而非返回 400
（原件既有行为，六域里唯一，见踩坑记录 A12）。不可信来源的入参须在调用点自行包一层。

### `async_mcp_tools(data)`

在 `async_mcp_client` 之上列出各 server 的工具。返回 `message` 会报告成功数与失败明细，例如「MCP 工具获取成功，共 0 个；失败 1 个: x: unhandled...」。

**单个 MCP server 不可用不会拖垮整轮对话**——agentscope 的 `_get_available_tools` 对每个 client 单独 try/except 并 `logger.warning` 跳过（源码注释明确说明：过期 token 或宕机的 server 不应结束会话）。

## 五B、`tools/rag/` — RAG 知识库工具

### `async_rag_tools(data)`

统一入口，`data["function"]` 选择：`write` / `read`（别名 `search`）/ `delete` / `delete_collection` / `list`。

公共配置段 `rag_config`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | `str` | 向量库类型，当前支持 `sqlite`（默认） |
| `sqlite_config` | `dict` | `{"path": 集合名, "base_dir": 数据目录}` |
| `vector_type` | `str` | 当前 SQLite 后端仅支持 `dense` |

业务参数：

| function | 参数 |
|---|---|
| `write` | `file_config`（`file_path`/`file_name`/`is_bytes`/`bytes`…）、`file_chunker`（`chunk_size`/`overlap`）、`embedding` 或 `embedding_model` |
| `read` / `search` | `query`（必填）、`top_k`（默认 10）、`doc_id`（可选）、`score_threshold`（可选）、`embedding` 或 `embedding_model` |
| `delete` | `doc_id`（必填） |
| `delete_collection` | 无 |
| `list` | 无 |

返回：

```python
# write
{"code":200, "data":["doc.pdf::0", ...], "message":"写入 N 个切片到 kb"}
# read
{"code":200, "data":[{"id","text","metadata","score"}, ...], "message":"命中 N 条"}
# list
{"code":200, "data":["kb"], "message":"共 1 个集合"}
```

文件解析默认 `require_file=True`，路径不存在直接 400，避免把路径字符串当正文入库。

## 六、参数归属速查

| 参数 | 属于哪层 | 说明 |
|------|------|------|
| `function` | `data` 顶层 | 所有域的 dispatcher 读 |
| `db_config` / `email_config` / `run_config` / `browser_config` / `mcp` | `data` 顶层 | 各域的连接/配置段，多数可平铺顶层替代 |
| `table` / `sql` / `filters` / `columns` / `order_by` / `offset` / `limit` / `pattern` / `database` | `data` 顶层 | db 业务参数 |
| `data`（db 写） | `data` 顶层 | 行数据，**与外层同名易混**，是 `args = {k: data[k] for k in (...,"data",...)}` 的产物 |
| `url` / `method` / `headers` / `params` / `json` / `verify` | `data` 顶层 | net 基础业务参数 |
| `run_config` / `browser_config` / `output_format` / `max_length` / `extraction` | `data` 顶层 | net 高级网络（crawl4ai 透传，不发明同义字段） |
| `command` / `output_limit` / `output_part` / `timeout` | `data` 顶层 | system 业务参数 |
| `allowed_databases` / `allowed_tables` / `denied_*` / `allow_write` | `db_config` 内 | **管控字段，只能服务端注入** |
| `check_write` / `check_read` / `allow_headed` | `configure_fs_policy()` 参数 | **文件闸门，只能平台装配时注入**（`net/_fs.py`，download 与 screenshot 共用） |
