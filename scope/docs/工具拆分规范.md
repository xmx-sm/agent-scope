# scope/tools 工具拆分规范

记录 `tools/` 的组织规则、刻意偏离、新增功能的流程，以及**如何重跑验证**。

> 切分器与验证脚本已按决策丢弃（原在 `/tmp/opencode/`，随重启消失）。本文档保留方法与结论，
> 使任何人可依此重建，而不必重新摸索踩过的坑。

## 〇、三轮改造，三个基线

本目录经历过三轮改动，**基线不同，勿混淆**：

| 轮次 | 目标 | 与 `agent_study` 原件的关系 | 验证方式 |
|---|---|---|---|
| ① AST 拆分 | 6 个单体 → 37 个文件 | **逐字节等价**（137 个可执行体 AST 全等、127 用例一致） | 第四节 ①②③ |
| ② 入参与错误返回统一 | 117 个函数改 data 入参 + 400 信封 | **故意破坏等价**（用户 2026-11-22 决策） | 第五节 |
| ③ crawl 合并回 net | 目录重组：`crawl/` 并回 `net/`，`_helper.py` 拆三层 | 逻辑逐函数对撞（175 项），旧信封层丢弃 | 第六节 |

②之后①的"可证明等价"不再成立，③又改变了文件组织——但**原件始终是行为基准**：
所有对撞验证仍以 `agent_study/scope/tools` 为准，只是差异被预先分类为「新增校验」而非「缺陷」。

②的完整契约见《参数说明.md》〇′ 节；③的动机与得失见下文第七节。

## 一、六条组织规则

1–4 来自①（文件怎么切），5–6 来自②（函数怎么写）。

| # | 轮次 | 规则 | 理由 |
|---|---|------|------|
| 1 | 拆分 | **入口 `main_<域>.py` 只做 `data["function"]` 路由**，不含业务逻辑 | 读一个文件即知该域有哪些能力；新增功能只动一处 |
| 2 | 拆分 | **一个 function 一个文件** | 单功能可独立阅读、单测、停用；diff 清晰 |
| 3 | 拆分 | **无状态辅助合并为该域唯一的 `_helper.py`** | 避免碎片化（曾出现 26 行只装一个函数的 `_smtp.py`） |
| 4 | 拆分 | **有状态 / 外部连接的模块保持独立** | 可变全局与连接生命周期有独立的正确性约束，混进 helper 会掩盖 |

| # | 轮次 | 规则 | 理由 |
|---|---|------|------|
| 5 | ② 统一 | **所有顶层函数入参一律 `data: dict = None`**，取消位置参数与 `**kwargs`；参数错误 `if` 判断后返回 400 信封，不裸抛 | 形态统一；消灭 `mcp`/`db` 的 `AttributeError`/`ValueError` 穿透 |
| 6 | ② 统一 | **返回一律 `{code, data, message}`**，但两类函数豁免：<br>① **信封机器**（`_ok`/`_err`/`_where`/`_to_bool_tuple`/`_bad_limit`，19 个）保持原生签名<br>② **纯副作用函数**（6 个）入参改 data 而**不套信封**，坏入参 fail-fast 抛 `ValueError` | ① 造信封的机器不能自己是信封，否则 `return _ok(x)` 要绕一层<br>② 无数据可返回，套信封是形式主义；调用点是自己的代码，传错类型应尽早崩 |

### 活对象放 `data` 本体，不套命名键

返回连接/客户端/配置对象/SSL context 等不可 JSON 序列化的活对象时，`data` 直接就是该对象：

```python
client = get_http_client({"verify": True})["data"]        # 而非 ["data"]["client"]
conn   = (await async_open_imap({"cfg": cfg}))["data"]
```

一次返回**多个**值时才用命名字典（`_write_where(...)["data"]["where"]`）。
理由纯粹是降低 249 处调用点的解包噪音——这是全量统一形态能拿回的唯一补偿。

### 跨域前缀约定（易错，踩过）

`_err` 加不加「错误：」前缀，各域原件本就不一致，**照抄原件**：

| 域 | `_err` 行为 | 路由提示文案 |
|---|---|---|
| `crawl` | **不加**前缀，msg 由调用方自带「错误：」 | 「暂不支持的 function」无前缀 |
| `net`/`system`/`mail` | 400 加、500 不加（`prefix=None` 时按 code 定） | 用 `prefix=False` 保持无前缀 |
| `db` | 固定加前缀 | 「未知 function」**有**前缀（原件即用白名单校验，措辞不同） |

⚠️ 第二轮初期我在 `system`/`mail` 误用了带前缀的 `_err` 装路由文案，造成「错误：错误：」
双重前缀与跨域不一致，被等价性测试抓到才修。**改任一处 `_err` 语义，六个域都要复查。**

判定"无状态"的标准是**碰不碰 socket、有没有模块级可变全局**，不是"同步还是异步"。
`mail/_helper.py` 里的 `imap_ssl_contexts` / `imap_connect_error` 是异步生态的一部分，但它们不建连，故归 helper；`_connection.py` 才管实际握手与放弃。

### 命名

- `_` 前缀 = 辅助层，**不应被业务代码直接调用**
- 无前缀 = 功能层，只由本域 `main_*.py` 调用
- 入口固定 `main_<域>.py`（`main_sys` / `main_net` / `main_crawl` / `main_mail` / `main_mcp` / `main_db`）

### 各域辅助层的实际命名

system 用 `_common.py`、net 用 `_client.py`、mcp 用 `_config.py`，**没有统一改名成 `_helper.py`**——
这三域的辅助层本就只有一个文件，为凑规则而改名只会制造无意义的 diff。规则 3 的意图是"别碎"，不是"名字必须叫 helper"。

## 二、刻意偏离与它们的现状

### ① `db/gate.py` 没并进 `_helper.py`

它是无状态函数，按规则 3 该进 helper。但内容是库级/表级白名单黑名单与 SQL 表引用校验，是这个工具的**业务核心**。

混进 helper 的后果：546 行安全逻辑失去独立可见性，改动它看起来像"顺手改个 helper"，而实际应当是显式的安全决策。

**若想推翻**：把 `gate.py` 的 10 个符号并入 `_helper.py` 即可，无环风险（`gate` 只依赖 `_helper`）。但建议保留独立。

### ② `crawl/_fs.py` 并进了 `_helper.py` —— **已被③推翻**

②里它有模块级可变全局 `_HOST_CTX`，按规则 4 该独立，但 `configure_fs_policy` 写它、
`_check_write`/`_check_read` 读它，三者必须同模块（拆开会破坏可变状态的可见性），
且它是"装配时写一次后只读"的配置注入，不是运行时状态。

**判据仍然有效**：写一次后只读的算无状态；运行中反复改的（如 `net/_client.py` 的
`_HTTP_CLIENT` 惰性单例）算有状态。

③ 合并 crawl 回 net 后，这一层被提为 **`net/_fs.py` 域共用层**——理由不再是"它该不该独立"，
而是"download 与 screenshot 必须共用同一闸门"（A21 的不对称）。原偏离②的结论（并入 helper）
被推翻，但**判据本身没错**：`_HOST_CTX` 依旧是"写一次后只读"，只是它现在服务两个功能。

### ③ `db` 的 `executors.py` 与 `dialect.py` 必须分开（不可推翻）

这不是风格选择，是**成环约束**：

- `dialect._sql_dialect_write` → `executors._pg_write`
- `postgresql._pg` → `dialect._sql_dialect_query`

若合并为一文件，`_pg → 合并文件 → _pg_write` 构成双向依赖。拆成两层后依赖严格单向。

**推翻了会怎样**：切分时报循环依赖，无法产出。这是唯一不可推翻的一条。

## 三、新增功能流程

以给 `net` 域加一个 `function="dns_lookup"` 为例：

1. **写 `tools/net/dns_lookup.py`**，导出 `async_dns_lookup(data) -> Dict[str, Any]`，
   顶部 docstring 写明入参、返回、调用示例（沿用现有风格）。
2. **在 `main_net.py` 加路由**：

   ```python
   try:  # 作为包导入（推荐）
       from .dns_lookup import async_dns_lookup
   except ImportError:  # 直接以脚本运行本文件
       from dns_lookup import async_dns_lookup
   ```

   并在 `async_req_tools` 的 `if function == "..."` 链里加一个分支，
   同步更新末尾错误文案的支持清单。
3. **更新 `main_net.py` 的模块布局 docstring**（列出新文件）。
4. **若要新辅助**：无状态的进 `_helper.py`（或本域的 `_common`/`_client`/`_config`）；
   引入新的进程级单例或连接池则新建独立模块，**不要塞进 helper**。
5. **更新 `docs/参数说明.md`** 的 function 表与 `docs/CODE_INDEX.md` 的文件表。

### 路由写法：`if` 链，不是注册表

现六个域一律用 `if function == "x": return await async_x(data)` 链。

曾试过 `FUNCTIONS = {"cmd_run": async_cmd_run}` 字典注册表，优点是错误文案的支持清单可自动生成
（`', '.join(FUNCTIONS)`），缺点是**偏离原件**，破坏了"可证明等价"。最终统一取 `if` 链，
代价是新增功能时要手改末尾文案。

**若你要改回注册表**：六个 `main_*.py` 都要动，且改动后等价性验证不再可比（见下节）。

## 四、如何重跑等价性验证

拆分的全部保证来自"与 `agent_study/scope/tools` 的原件对撞"。原件是基准，**不要删**。

改完工具后按以下六道重建验证（脚本需重写，但方法已定，不必重新摸索）：

### ① 结构等价（最强，先跑这个）

把原件与拆分后该域所有模块的**可执行体 AST dump 做成多重集对撞**：

- 排除：模块 docstring（`ast.Expr` + `Constant`）、`import` 语句（切分器会重新分布，属结构调整非逻辑变更）
- 比对：函数、类、顶层赋值、`if` 块
- 判据：`Counter(原件) - Counter(拆分) == 空` 且反向也为空 → 零增删改

**上次结果**：system 4 / net 11 / crawl 30 / mail 25 / mcp 7 / db 60 个可执行体，6/6 域全等。

### ② 行为等价

同输入喂 orig/new，比对归一化后的返回。归一化必须处理两类噪声：

- **`__file__` 路径**：原件错误标识形如 `/abs/path/async_db_tools.py_async_db_tools`，拆分后路径变了。
  正则剥成 `<FILE>_函数名`。注意 `db` 的 `_err` 后缀是**硬编码** `_async_db_tools`（不随调用方变），
  而 `system` 这类每函数自拼 `f"{__file__}_{fn}"` 的，归一化后才可比。
- **实时网络易变字段**：`date`/`x-req-id`/`cf-ray`/`server-timing`/`age`/`alt-svc`/`origin`/`timestamp`
  置为 `<VOL>`，否则两次请求差 1 秒就会报"不一致"（曾在 net case#0 误报）。

**上次结果**：127/127 用例一致。

**必须包含健壮性用例，且逐域独立覆盖**：每个域都要测 `None` / `"notdict"` / `123` / `[1,2]` 四类非法入参。
不能靠"别的域测过"推断——`db` 的 43 个用例全是合法三元组，漏了这一类，
直到补文档时才发现它对非 dict 裸抛 `ValueError`/`TypeError`（`mcp` 更是完全无防护，抛 `AttributeError`）。
这类缺陷**原件与拆分版行为一致**，所以等价性测试会通过它，但它是真实的健壮性缺口。

### ③ db 必须比对落盘终态

`db` 的写操作光比返回值不够。正确做法：

- **每个用例为 orig/new 各自重新播种独立库**（否则第二次看到的是被第一次改过的状态）
- 执行后 dump 全库：所有表的 DDL + `SELECT * ORDER BY rowid`，序列化为字符串比对

SQLite 是唯一无需服务端就能真跑的方言，用它覆盖全部 10 个 function + 闸门场景。
**上次结果**：43/43，返回值与落盘终态双双一致。

### ④ 静态检查（合并 helper 后必查）

两道 AST 检查，抓①抓不到的两类问题：

- **顶层名称冲突**：合并后两个来源带来同名符号，后者静默覆盖前者
- **漏 import**：合并改变了 import 边界

实现要点（**这里踩过坑**）：

- 收集"已绑定名字"必须**独立处理 `ast.Lambda` 的形参**，不能挂在 `FunctionDef` 的 `elif` 分支里。
  漏收会把 `trim = lambda vs: [...for v in (vs or [])]` 这类正常代码误报成未定义引用
  （曾在 crawl 上报出 `vs`，对原件跑同一检查也报，才识破是自己检查器的缺陷）。
- `except X as e` 里 `e` 在 AST 中是 **`str`**，不是 `ast.Name`，取 `n.name` 会 `AttributeError`。
- **必须做负控**：故意造一个漏 import + 顶层重名的探针文件，确认检查器两类都能抓，
  否则"全绿"可能只是检查器失效。

**上次结果**：名称冲突 0 / 漏定义 0（拆分版与原件两侧均干净）。

### ⑤ 导入与自测块

- 枚举 `tools/**/*.py` 逐个 `importlib.import_module`（上次 37/37 通过）。
  ⚠️ **不要用 `pkgutil.walk_packages`**——`tools/` 无 `__init__.py` 是 namespace package，
  walk 返回 0 个模块，会得到虚假的"全通过"。
- `python -m tools.<域>.main_<域>` 跑四个有自测块的入口（system/net/mail/mcp）。

### ⑥ agentscope 集成

走真实 `Toolkit.call_tool(ToolCallBlock, AgentState)` 派发路径，而非裸函数调用。要点：

- `ToolCallBlock.input` 是 **JSON 字符串**，不是 dict
- payload 要包一层：`json.dumps({"data": {...}})`（见《参数说明.md》〇 第 3 条）
- `get_tool_schemas(groups)` 必须显式传 `state.tool_context.activated_groups`，
  传 `None` 只见 basic 组
- 未激活组的工具应报 `ToolGroupInactiveError`，`state=error`——这是闸门生效的证据

## 五、第二轮改造的验证方法

入参统一破坏了与原件的等价性，所以验证目标从"证明零差异"变成**"把每一处差异预先分类"**。
五道验证，脚本需重写，方法与判据已定：

### ① 坏入参不裸抛（本轮的核心目标）

对每个 `(data)` 单入参的可调用者，喂 7 类坏值：`None` / `"notdict"` / `123` / `[1,2]` / `3.14` / `True` / `False`，
断言返回 400/500 信封而非抛异常。三个必要豁免：

- **副作用函数**（`exclude`）：它们 fail-fast 抛 `ValueError` 是设计
- **lenient 函数**：`get_http_client`/`get_email_config`/`decode_header_value`/`strip_html` 等
  把 `None`/未知键当"用默认值"，只要求不裸抛、不要求 400
- **生成器**：`imap_ssl_contexts` 是**同步**生成器，`fn(b)` 得到 generator 对象而非 dict。
  probe 必须分别处理 `isasyncgenfunction` / `isgeneratorfunction` / `iscoroutinefunction`
  ——初版漏了同步生成器分支，报出一片假失败

### ② 纯函数适配器对撞（证明逻辑等价，只是外壳变了）

辅助函数签名变了，无法直接对撞。写适配器把新版信封还原成原件形状再比：

```python
# 原件: O._db_same(a, b) -> bool
# 新版: NG._db_same({"a":a,"b":b})["data"] -> bool
# 适配器让两者可比
```

**必须双侧归一化** `__file__` 路径——只归一化新版会报出假差异（我在 system 踩过：
原件的 `data` 字段没归一化，7 项误报）。归一化要分两级：
`norm_err_path`（保留函数名后缀）用于第一轮；本轮因 `_err` 的 `where` 也改了，
需用更彻底的 `re.sub(r"/.*?\.py_.*", "<FILE>", v)` 连后缀一起抹掉。

**差异必须分类，不能一律判失败**：

| 类别 | 判据 | 处置 |
|---|---|---|
| 逻辑等价 | 归一化后完全相等 | 通过 |
| 新增校验拦下原件放行的输入 | 新版 400 且原件成功或静默跳过 | **预期收益** |
| 新版多给类型诊断 | 两侧都 400，新版含「收到 <类型>」而原件没有 | **预期收益** |
| 新版修掉内部异常文案泄漏 | 原件 message 含 `invalid literal for int()` 等 | **预期收益** |
| 落盘不同 | — | **严重，必须查** |

### ③ 安全逻辑专项（db 闸门 / mail TLS / crawl 文件闸门）

改造安全代码时，"返回值形状变了"不足以证明"判定没松动"。必须单独断言：

- 每个闸门：两侧**均** 400，**且执行后库未被改动**（查行数，db 10 个闸门 × 2 项）
- `mail` 的 SMTP 强制 TLS：非 465 端口 STARTTLS 升级失败必须**拒绝**（防授权码明文过网）
- `crawl` 的文件闸门：平台注入的回调**契约仍是 `(bool, str)` 元组**——
  本层内部转信封，但 `_to_bool_tuple` 兼容两种写法，平台侧无需改注入代码。
  用"回调实收参数是否仍是 path 字符串"验证契约未破

### ④ 跨域一致性

本轮最大的新风险是**域间不统一**。逐项断言：

- 六域入口 × 5 类坏入参 → 全部 400 + 三键齐全 + 无一裸抛
- 路由提示文案：允许 `db` 用「未知 function」而其余用「暂不支持」（原件既有差异，见踩坑记录 A19），
  但六域都必须**附支持清单**
- 校验类错误统一带「错误：」前缀
- `_err` 的前缀语义逐域复查（本轮在此踩过双重前缀）

### ⑤ 静态检查

同第四节 ④，但本轮**必须查未使用 import**——改造删掉了大量手拼的
`f"{os.path.abspath(__file__)}_xxx"`，`os` 常变成孤儿 import（本轮查出 6 处）。


## 六、第三轮：crawl 合并回 net

### 动机（决定性依据不在代码结构，在装配层）

`agent_study/tools/__init__.py` 本就是：

```python
net_tools = [FunctionTool(async_req_tools)]
if _CRAWL_AVAILABLE:
    net_tools.append(FunctionTool(async_crawl_tools))   # ← 同一个组
ToolGroup(name="net",
          description="网络工具：HTTP 请求、天气查询、文件下载；另有 pro 网页抓取（浏览器渲染…）",
          tools=net_tools)
```

原作者的心智模型里 crawl 就是 net 组成员，描述文案「pro 网页抓取」对应本次的定位「高级网络请求」。
①把 crawl 独立成域时我给的理由是「两种能力 + 各自有可变全局」——**后半句站不住**：
`net` 有 `_HTTP_CLIENT`/`_HTTP_CLIENT_INSECURE`，`crawl` 有 `_CRAWLER`/`_START_LOCK`，
两边都有可变全局，这构不成区分。合并后 net 是 17 文件 / 30 函数 / 1722 行，
小于 db（9 文件 / 46 函数 / 2533 行），规模上毫无问题。

### 为什么保留两个入口而不合并 dispatcher

- 平台需要能单独停用 crawl（慢、贵、起浏览器）而保留 http_request
- 合并会让黑盒 schema 的参数面翻倍，模型更易填错（B1/B3 的既有问题会更严重）

### 辅助层的重新划分

`crawl/_helper.py`（22 个顶层符号）按职责拆成三份，旧信封层三个符号丢弃：

| 新文件 | 收什么 | 为什么 |
|---|---|---|
| `net/_envelope.py` | `_where`/`_ok`/`_err` | net 有四个辅助文件，信封塞进任一个都会让其余三个横向依赖它（文件闸门依赖 httpx 单例，语义不成立）。**六域里唯一独立成文件的信封层** |
| `net/_fs.py` | `_HOST_CTX`/`configure_fs_policy`/`_to_bool_tuple`/`_check_write`/`_check_read` | **提到域共用层**，download 与 screenshot 同走此闸门（修 A21） |
| `net/_render.py` | 上限常量、`logger`、配置构建、三个副作用钳制、`_pick_output`/`_fail` | 无状态，与连接层无关 |

净效果：信封机器 19 → **16** 个（三份重复被消掉一份）。

### 本轮修掉的两处

| 项 | 内容 |
|---|---|
| **A21 闸门不对称** | `download` 原先直接 `open(save_path,"wb")` 落盘、完全不过闸门，而同域 `screenshot` 走 `_check_write`。平台注入的租户约束对 download 失效（可写到 uploads 根之外）。现共用 `_fs.py`，判定在 `makedirs` **之前**（建目录本身也是写操作） |
| **A22 `_err` 参数倒置** | `crawl._err(where, msg)` vs `net._err(message, func_name, code, prefix)` —— 前两个参数都是 `str`，**写反不报错**只产出垃圾（message 变函数名、data 变中文文案）。跨文件复制粘贴错误处理代码时最易撞，静态检查抓不到（类型完全合法）。现全库统一 |

### 本轮的验证

① 用 AST 脚本做 `_err` 顺序转换与 500 统一，**连吃两个静默 bug**（详见踩坑记录 C6）：
`col_offset` 是字节偏移导致吃字符（损坏跨到函数边界，靠 `py_compile` 暴露）、
正则吃掉 `return` 关键字（**语法合法**，异常路径返回 `None` → agentscope dump 成 `"null"` 给模型，
错误信息全丢，靠静态检查的「未定义引用」间接暴露）。

结论：**批量改写源码的脚本跑完必须立刻做 AST 级校验**（编译 + 未定义名 + 行为对撞），
不能只看"脚本没报错"。若 ② 的 `_err` 当时已可调用，它会被完全静默地带上线。

② 合并后逐函数对撞 175 项：`_valid_names` 形参名单 3/3、`_build_config` 合法配置逐属性一致、
`_clamp_configs` 原地钳制 4/4、`_apply_wait_for` js_code 翻译 5/5 逐字符、
`_pick_output` 8/8、`_fail` 5/5、文件闸门 4/4 判定与文案逐字一致、
**平台回调的 `(bool, str)` 元组契约不变**（回调实收参数仍是 path 字符串）、
`__all__` 两项再导出可取用、`crawl4ai` 缺失由裸抛改 400 信封。

③ download 闸门的不对称消除用**同路径双工具判定**证明：cwd 外两侧均拒、cwd 内两侧均放行，
平台注入后按其策略且元组契约未破。

## 七、附录：切分器实现要点（重建时照此做）

若需重建切分工具，核心约束：

1. **按 AST 顶层块的行范围原样抽取源码**（`lines[start-1:end]`），
   **绝不手工重打函数体**——6 个文件 3335 行，手工转录必有错。
2. **向上吸收紧邻注释**：从 `node.lineno` 向上走，遇 `#` 或空行继续，撞到上一个块的 `end_lineno` 即停。
   否则函数上方的说明注释会与函数分离。
3. **依赖判定只用 AST 真实节点**（`Name` / `Global` / 属性根 / `alias`），
   **不扫注释、不扫任何字符串常量**。docstring 里提到的函数名、
   `logging.getLogger("async_crawl_tools")` 的日志器名都不是依赖。
   （本工具初版用正则扫标识符，在 crawl 上凭空造出 `crawl.py → main_crawl.py → crawl.py` 的假环。）
4. **`__all__` 单独显式处理**：其中列出的名字需真实绑定在本模块，构成**再导出依赖**。
   这保证了 `crawl/main_crawl.py` 的 `__all__` 契约不被拆散。
5. **import 按使用者重新分布**：某 import 块绑定到 `used ∪ reexport` 才带入目标文件，
   避免无用 import。
6. **切分源固定为原件**，产物目录先清空再写 → 幂等，可反复重跑。
   （曾把源指向已拆分的产物目录，删掉原件后重跑直接 `FileNotFoundError`。）
7. **模块 docstring 生成要换行包裹**：内容以引号结尾时（如 `function="find_email"`），
   `f'"""{x}"""'` 会拼出 `""""` 而语法错误。用 `f'"""\n{x}\n"""'`。
