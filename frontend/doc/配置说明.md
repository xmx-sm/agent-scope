# frontend 配置说明

前端配置分两类：

1. **构建/启动配置**：`frontend/.env`，Vite 启动时读取，修改后需重启 dev server / 重新 build。
2. **运行时业务配置**：来自后端的 `/public/site`、`/auth/me`、`/admin/configs`，无需重新构建。

---

## 一、`.env`

模板见 `frontend/.env.example`，实际 `.env` 不入库。

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITE_APP_TITLE` | Agent Scope Platform | 顶栏与登录页标题的本地兜底 |
| `VITE_PORT` | 5182 | 开发服务器端口 |
| `VITE_BASE` | /agent_scope/ | 子路径部署前缀，同时作为 Vue Router 的 `BASE_URL` |
| `VITE_PROXY_TARGET` | http://127.0.0.1:8000 | API 代理目标 |
| `VITE_API_BASE` | /agent_scope/api | Axios baseURL 与 SSE/下载地址前缀 |

注意：

- Vite 只暴露 `VITE_` 前缀变量到客户端
- 生产构建时保持 `VITE_BASE=/agent_scope/`、`VITE_API_BASE=/agent_scope/api`，
  由 Nginx 在 `5080` 端口将 `/agent_scope/api` 转发到后端 `/api`
- 修改 `.env` 后必须重启 `npm run dev`，生产需重新 `npm run build`

## 二、后端下发的运行时配置

### 2.1 登录/注册页

`GET /api/public/site`：

| 字段 | 用途 |
|---|---|
| `site_name` | 登录页标题 |
| `site_description` | 副标题 |
| `allow_register` | 是否显示注册入口 |
| `default_avatar` | 预留：默认头像 URL |

### 2.2 登录后

`GET /api/auth/me`：

| 字段 | 用途 |
|---|---|
| `user` | 昵称、用户名、角色、头像 |
| `permissions` | 菜单与路由可见性 |

`permissions` 是**有效权限**，已包含角色权限、单独授权、逐级收缩、临时授权。

### 2.3 默认设置（超管）

`GET /api/admin/configs` 返回分组配置，前端按 `group` 展示：

- 站点：名称、描述、默认头像
- 账号：注册开关、默认角色、密码长度、登录有效期、维护模式
- 安全：限流开关、登录/注册次数与窗口
- 界面：默认分页、状态刷新间隔

当前前端仍固定运行状态 10 秒刷新；`status_refresh_seconds` 已入库，后续可接入。

## 三、移动端适配

| 项 | 约定 |
|---|---|
| 断点 | `max-width: 767px` |
| 侧栏 | 桌面固定；移动端抽屉 |
| 用户列表 | 桌面表格；移动端卡片 |
| 弹窗 | 移动端 `calc(100vw - 24px)` |
| 安全区 | `viewport-fit=cover` + `env(safe-area-inset-bottom)` |
| 字号 | 输入框使用 Element Plus large，避免 iOS 自动放大 |
| 分页 | 移动端隐藏总条数、减少页码按钮 |
| 状态页 | 4 列 → 2 列 → 1 列自适应 |

布局 CSS 在 `src/styles/main.css` 与各页面 `<style scoped>` 中。

## 四、权限与菜单

菜单项配置在 `Layout.vue::allMenus`：

```js
{ path: '/permissions', title: '我的权限', icon: Key, permission: 'permissions.self' }
```

显示条件：

1. `superAdmin: true` 的项仅 `user.role === 'super_admin'` 可见
2. 否则要求 `isSuperAdmin || permissions.includes(permission)`

路由守卫同步校验 `meta.permission` 与 `meta.superAdminOnly`，服务端仍会再校验一次。

## 六、部署要点

1. `VITE_BASE=/agent_scope/`、`VITE_API_BASE=/agent_scope/api`，由 Nginx 将 `/agent_scope/api` 转发到 FastAPI
2. 前端 history 路由需要 Nginx `try_files $uri $uri/ /agent_scope/index.html`
3. 静态资源可加长缓存，`index.html` 不缓存
4. 当前部署：Nginx 监听 `5080`，访问 `http://<host>:5080/agent_scope/`；
   Nginx 配置见仓库 `deploy/nginx/agent_scope.conf`

## 七、v0.3.0 菜单与配置

### 动态菜单

- 来源：`GET /api/menus/mine`
- 缓存：`localStorage.menus`
- 登录、`fetchMe()`、权限收缩后自动刷新
- 两级结构：`children` 存在时渲染分组
- 侧栏收起时展平为图标

### 菜单配置（超管）

- 页面：默认设置 → 菜单配置
- 接口：`/admin/menus` CRUD、`/admin/menus/reorder`
- 图标：Element Plus 图标名（`Grid`、`Key`、`Setting`、`Monitor` 等）
- 权限点下拉来自 `/admin/permissions` 的 `all_permissions`

### 新配置分组

默认设置自动按 `group` 展示：

- **AI**：模型地址、模型、Key、温度、上下文、Embedding
- **Scope**：agent.* / rag.* 默认值
- **邮箱**：SMTP、发件人、TLS、收件默认值

`float` 使用 `el-input-number`（步长 0.1）；`secret` 使用密码框，提交 `******` 表示不修改。

## 八、v0.3.2 菜单个性化

- 用户偏好接口：`GET/PUT/DELETE /api/menus/prefs`
- 可配置：`order`（一级/子级顺序）、`hidden`（隐藏项）
- `menu.personalize` 固定不可隐藏
- 入口：用户头像菜单 → 菜单个性化，或「我的」分组
- 恢复默认：页面「恢复默认」按钮

默认菜单由超管「菜单配置」决定；用户个性化只覆盖顺序与显示，不改变权限。

---

## 九、v0.4.0 Agent 配置

- 页面：`/admin/agent`
- 配置域：`domain=agent`
- 厂商下拉来自 `/admin/agent/providers`，支持自定义
- 「获取模型」需要 API 地址；Key 未修改时使用数据库中的真实值
- 对话模型与向量模型字段独立
- 系统设置只读取 `domain=system`，避免 AI/Scope 混入

## 十、v0.5.0 AI 工具权限

- 默认全部工具
- 超管：用户管理 → AI 工具 → 全部 / 单独授权
- 上级：管理下级 → 收窄工具
- 本人：我的权限 → AI 工具
- 页面和菜单权限仍由角色权限与菜单配置控制
